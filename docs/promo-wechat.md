# Dazi：把 Claude Code 装进手机遥控器

> 你的本地算力很强，但你总不能一直坐在电脑前。
> Dazi 让你用手机给本地的 Claude Code 派活、看计划、批任务、甚至直接开终端——数据一步都不上云。

---

## 写在前面：一个真实的场景

你有一台 4090 服务器，或者一台配置很高的开发机，跑着 Claude Code CLI，干起活来又快又好。可问题来了——

- 跑长任务时，你只能干等着，走开一会儿就怕它中途卡住；
- 出门在外突然想到一个活，想让它先跑着，却够不着家里的机器；
- 想让 AI 帮你自动定时跑些琐碎活，又怕它无人值守时"放飞自我"删库跑路。

**Dazi 就是为这些问题做的。** 它不是又一个云端 AI 平台，而是给本地的 Claude Code 套上了一层「任务管理 + 远程调度 + 人机审批」的外壳，让你的手机变成这台机器的遥控器。

数据、执行、记忆，全在你自己的机器上；手机只是一个轻薄的窗口。

---

## Dazi 是什么

一句话：**Dazi 是 Claude Code 任务的本地化协作调度中枢。**

它把每一个任务变成一个本地文件夹，集中管理任务的上下文（README、参考资料、笔记、产出），一键把这些上下文交接给 Claude Code CLI；同时跑一个本地守护进程（daemon），让你的手机或任意浏览器可以远程查看任务、审批计划、定时调度，甚至直接打开一个交互式终端，远程驱动这台机器上的 claude。

它覆盖三个端：

- **桌面端**（macOS / Windows）：基于 Tauri 的原生应用，管理任务、编辑上下文、内置终端。
- **手机端**（iOS / Android）：Flutter 原生 App，远程查看、审批、调度、开终端。
- **浏览器**：手机浏览器直接打开就是一个 PWA，不装 App 也能用。

## 它能做什么：六大核心功能

### 功能一｜任务即文件夹，把上下文管起来

Dazi 里，每个任务就是一个文件夹，结构清晰：

```
我的任务/
├── README.md        ← 同时是交给 Claude 的提示词
├── references/      ← 参考资料
├── notes/           ← 你的笔记
├── output/          ← Claude 的产出
└── .dazi/           ← 记忆与运行日志（自动维护）
```

**关键设计**：`README.md` 本身就是提示词。模板会引导你写清楚角色、背景、目标、约束、交付物、验收标准——等于边整理任务边把 prompt 写好了，不用再额外维护一份。

任务分三类：**一次性、定时、循环**。支持状态、优先级、标签、起止日期，还能归档、移入回收站，或把已有的文件夹直接关联进来（用软链接，不污染原目录）。

工作区建议放在 iCloud Drive，桌面端多设备同步；手机端则通过 daemon 远程访问同一份工作区。

### 功能二｜一键交接给 Claude Code

这是 Dazi 最省心的地方。你不用手动复制粘贴一堆上下文给 claude——点一下"交接（Handoff）"，Dazi 会自动把以下内容拼成一份完整 prompt 注入 Claude：

- 任务的 README（你的需求与约束）
- references 里的参考资料
- 全局记忆 + 本项目记忆（见功能五）
- 同工作区下兄弟项目的索引（供跨项目检索）
- 最近的运行日志

Claude 拿到的，是一个"前因后果都齐了"的任务，而不是一句干巴巴的指令。

### 功能三｜手机审批流：先看计划，再让它跑（核心卖点）

这是 Dazi 区别于"裸跑 claude"的最大差异点，也是面向远程/无人值守场景的安全护栏。

流程是这样的：

1. 远程或定时触发一个任务，**不会直接开跑**；
2. Claude 先以"计划模式"只读地分析任务，产出一份 Markdown 执行计划；
3. 这份计划被实时推送到你的手机；
4. 你在手机上读计划，**批准**——Claude 才以完整权限真正执行；**拒绝**——只记录、不执行。

换句话说：**AI 先打报告，你签字才放行。** 既能享受自动化的省力，又把"放飞自我"的风险摁住了。尤其适合让 claude 在你的代码仓库、服务器上动手的场景。

### 功能四｜无人值守的 Autopilot

对于那些你信任、可以放手让它跑的任务，Dazi 提供 Autopilot 模式：

- 以 `bypassPermissions` 模式 headless 跑 claude，自主把任务推进到可交付状态；
- 带硬超时（默认 10 分钟）、进程组级别的 kill 防止孤儿进程；
- 执行结果以 JSON 解析，journal 自动回写。

它和审批流搭配使用最舒服：**陌生任务走审批，熟悉任务走 Autopilot**，按任务性质自己拿捏。

### 功能五｜分层记忆系统：越用越懂你

这是另一个差异化亮点。Dazi 维护两层记忆，每次交接都会带上：

**全局记忆**（放在 `~/.dazi/`，跨所有任务共享）：

| 文件 | 内容 |
|---|---|
| `profile.md` | 你的用户画像（身份、偏好、工作方式） |
| `facts.md` | 世界事实（你的服务器、设备、账号信息） |
| `patterns.md` | 跨项目复用的模式与约定 |
| `changelog.md` | 记忆自身的变更记录 |

**项目记忆**（放在每个任务的 `.dazi/` 里）：

| 文件 | 内容 |
|---|---|
| `journal.md` | 这个任务的协作流水（每次执行发生了什么） |
| `context.md` | 当前进展的快照 |

更聪明的是，Dazi 在注入 prompt 时会带上"记忆回写约定"，让 Claude 自己判断新产生的信息该写回哪个文件。**于是任务跑得越多，Claude 对你、对项目、对环境的理解就越深**，不用每次从头解释"我用的什么服务器、代码风格是啥样"。

### 功能六｜远程交互式终端：手机直接开本地 shell

有时候任务复杂到需要"盯着看、随时插话"，Dazi 给每个任务配了一个常驻的交互式终端：

- 手机/网页通过 WebSocket 连到本地的 PTY 会话，双向实时收发；
- **256KB 回放缓冲**，断线重连自动回放历史输出，PTY 保活——地铁里断一下也不会丢上下文；
- 三种启动模式：纯 Shell、Handoff（注入上下文跑 claude）、Continue（`claude -c` 续上次会话）；
- 手机端配齐虚拟功能键：Esc / Tab / 方向键 / Ctrl+C / Ctrl+D / PgUp / PgDn。

相当于**把你的本地终端装进了口袋**。手机上敲命令，跑在 4090 上，输出实时回传。

## 它怎么保证安全

把本地机器开放给手机访问，安全是绕不开的问题。Dazi 的做法：

- **PIN 配对**：首次启动 daemon 生成 6 位 PIN，手机扫码或手输，换取长期 device_token；
- **Token 哈希存储**：token 以 sha256 存在 `~/.dazi/devices.json`，可随时吊销；
- **强制审批**：远程/定时触发默认走计划审批流，不裸跑；
- **仅内网访问建议**：默认端口 7878 监听 0.0.0.0 供局域网使用，异地远程建议配 Tailscale，**不要做公网端口转发**。

核心思路：**手机是遥控器，但钥匙始终在你手里。**

## 一个真实跑通的案例：手机遥控 4090

这不是 PPT。我们在一台 Ubuntu 22.04 的 4090 服务器上做了端到端验证：

- daemon 编译成功（3.8M 二进制），以 systemd 用户服务自启、开启 linger；
- claude CLI 探活通过，配 API key 走中转，`/health` 全绿；
- 完整链路实测：**配对 → 建任务 → 写 README → 设循环调度 → 发起计划 → Claude 真实产出计划 → 手机批准 → Claude 真实执行 → 产出文件实地确认、journal 自动记录**。

全链路打通。也就是说，"团队成员用手机/PC 远程调度本地 4090 上的 claude"这件事，已经是可以跑起来的现实，而不是构想。

## 技术栈一览

给技术读者交代一下底子：

| 层 | 技术 |
|---|---|
| 桌面端 | Tauri 2 + React 19 + TypeScript + Vite 7 + Tailwind 3 + Zustand |
| 桌面终端 | xterm.js（fit / unicode11 / webgl 加速） |
| 后台守护 | Rust + Axum 0.7（WebSocket）+ tokio + portable-pty |
| 核心业务库 | Rust（桌面端与 daemon 共用，逻辑下沉） |
| 移动端 | Flutter ≥3.6 + Riverpod + freezed + Dio + xterm.dart |
| Markdown 编辑 | Milkdown Crepe |
| 发布 | GitHub Actions（tauri-action，自动出 .dmg / .exe / .msi） |

三端共享一个 Rust 核心库，业务逻辑只写一遍；桌面与 daemon 之间、手机与 daemon 之间，统一走 WebSocket 做事件推送与终端流。

## 怎么用起来

**只要桌面端的用户**：到 GitHub Release 下载 .dmg（macOS）或 .exe（Windows），安装后首次启动选一个工作区文件夹即可。

**想要手机远程**：在工作机或服务器上跑起 daemon——
- macOS：`install-daemon.sh` 装 LaunchAgent，登录自启；
- Linux：`install-daemon-linux.sh` 装 systemd 用户服务 + linger；
- 启动后终端会打印局域网地址和 6 位 PIN，手机扫码或手输完成配对；
- 异地远程建议配 Tailscale，不要公网暴露。

**不想装 App**：手机浏览器直接开 `http://<你的机器IP>:7878`，PWA 可"加到主屏"，体验接近原生。

## 适合谁用

- **重度使用 Claude Code CLI 的开发者/研究者**，有一台本地开发机或 GPU 服务器；
- 想在**移动端随时给本地 claude 派活、审批计划、看结果**的人；
- **小团队远程共享一台强力机器**跑 claude 任务，需要调度与审批协作的。

如果你的场景是"完全云端、不想碰本地部署"，那 Dazi 目前不是为你准备的——它主打的就是"数据与执行在本地，手机只做遥控"。
